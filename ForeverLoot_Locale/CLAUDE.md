# ForeverLoot_Locale (locale companion)

Owns every **non-English name table** (items, instances, bosses, professions, trade skill
categories and tools) and, once a UI-string registry exists in the core, translated UI strings:
the generated ones, and on a non-English client the item names it learns in-game
(`ForeverLootLocaleDB`). Depends on `ForeverLoot` (`## Dependencies: ForeverLoot`) and talks to
it only through the public API (`Data.names`, `Data:GetItemIDs`, `Data:AddNames`,
`RegisterCommand`, `Log`/`LogAt`). Rules for all addons are in the root `CLAUDE.md`; the
ownership contract is `docs/architecture.md`.

## Files (`ForeverLoot_Locale.toc`, in load order)

- `ForeverLoot_Locale.lua` — the bootstrap. Declares the private-table class `ForeverLootLocale`
  (its `---@field`s are here, there is no `types.lua`), stores `name`, `api` = `ForeverLoot`,
  `coreAPIVersion`, and `log`, a tiny logger whose `chat` / `info` / `debug` forward to
  `ForeverLoot.Log` / `ForeverLoot.LogAt` so output shares the core's prefix and level setting.
- `db/generated/` — **generated by `npm run gen`, never hand-edited.**
  `locales/<locale>/items.lua`, `instances.lua`, `bosses.lua` and `crafting.lua` (profession,
  trade skill category and tool names) for every non-English locale in
  `.contribute/data/config.json` (`locales`: deDE, esES, esMX, frFR, itIT, koKR, ptBR, ruRU,
  zhCN, zhTW), plus `items.lua` for any other locale that has been scanned in-game. There is no
  loader XML: the TOC lists the four files as `db\generated\locales\[TextLocale]\<file>.lua`,
  a path variable the client resolves to its text locale, so only the client's own language is
  read at all. A missing file is a `LUA_WARNING` at login, so every client language (`enUS` and
  `enGB` included, whose English names are in the core and `ForeverLoot_Database`) has all four files, comment-only placeholders
  where there are no names; `check:addons` enforces it. Each file with names still starts with
  `if GetLocale() ~= "<locale>" then return end`. Excluded from LuaLS and StyLua.
- `src/db.lua` — `app.dbDefaults` for AceDB:
  `global.locales[locale] = { build?, items = { [itemID] = name }, missing = { [itemID] = true } }`
  (a `["*"]` default, one entry per client language), and the `ForeverLootLocale.DB` types.
- `src/ace.lua` — `app.addon`, the AceAddon object. `OnInitialize` opens `ForeverLootLocaleDB`;
  `OnEnable` registers `/fl locale [rescan]` through `ForeverLoot:RegisterCommand`, `OnDisable`
  unregisters it.
- `src/itemnames.lua` — `app.itemNames`, the Ace module that learns item names (below).

## What `itemnames.lua` does

The generated item names come from wago.tools' tables, which lack the items this server added or
changed (about 18% of the scanned items). The client knows those in its own language once it has
fetched them, so on a non-English client:

- `OnInitialize` (ADDON_LOADED, after every generated file has run): clears `missing` when the
  client build changed, drops saved names the shipped files now have, and registers the rest with
  one `Data:AddNames(locale, "items", …)`.
- `OnEnable` (PLAYER_LOGIN) starts a lookup `START_DELAY` = 15 s later (an `info` line says
  how many names it looks up): every id from
  `Data:GetItemIDs()` (the item rows `ForeverLoot_Database` adds; without that addon there are
  none and nothing is looked up) without a name in `Data.names[locale].items` and not `missing`. `BATCH` = 5
  ids per `INTERVAL` = 0.5 s (10/s, a fifth of `/fl scan`), none while `InCombatLockdown()`; a
  cached item is read at once, others through `C_Item.RequestLoadItemDataByID` and
  `ITEM_DATA_LOAD_RESULT`. The name from `C_Item.GetItemInfo` goes into the saved table right
  away and to `Data:AddNames` every `FLUSH_INTERVAL` = 30 s and at the end (each call invalidates
  the core's search and sort caches); a failed load marks the id `missing`. `SETTLE` = 5 s waits
  for the last answers; ids that never answered are asked again next session. The result is one
  `info` line when names were learned.
- `/fl locale` prints progress or the saved counts; `/fl locale rescan` clears `missing` and asks
  for every learned item again too.

English clients (`GetLocale() == "enUS"`) keep no state and run nothing; every English name is in
the core (item names: in `ForeverLoot_Database`, or from the client).
At login they get one `info` line saying the addon isn't needed there and can be disabled.

## How names flow

The core keeps the generated `enUS` instance, boss and crafting names as its standalone fallback
(`ForeverLoot/db/generated/locales/enUS/`), `ForeverLoot_Database` the `enUS` item names with
the item rows; the generator (`src/generate.ts`, `build()`) routes
every other locale here. Item names come from wago.tools' `ItemSparse` for the configured
locales, for the scanned items whose English name there matches the scan (about 82% of them),
and from in-game scans on a client of that language (a deDE scan adds German names next to the
English ones in `.contribute/data/items/*.json`), which win over the table's; at runtime
`itemnames.lua` adds the ones still missing. Instance, boss, profession, category and tool names
come from wago.tools for the configured locales. The core resolves an item name as client locale
→ enUS → `C_Item.GetItemInfo` → `"Item #id"` (the other kinds stop at enUS) and searches both the
client-locale and the English name; `AddNames` fires `OnDataChanged`, so late registration
refreshes open views.

## Adding a locale

Add it to `locales` in `.contribute/data/config.json` (instance, boss, profession and item names
from wago.tools) and/or scan items on a client of that language and `npm run import`, then
`npm run gen`. Nothing under `db/generated/` is edited by hand. A client language that is not
configured still gets its item names from `itemnames.lua`, all of them looked up in-game.
