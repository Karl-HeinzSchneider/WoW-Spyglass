# ForeverLoot_Database (item database companion)

Owns **every scanned item row** (`Data.items`) with its English name, and the **Items** module:
the whole database as one searchable, filterable list. It is split from the core because those
23k rows are most of the addon's memory (~34 MB of ~44 MB measured in-game) and load time; the
core works without them, taking what its lists show from the client. Depends on `ForeverLoot`
(`## Dependencies: ForeverLoot`), uses only the public API (`Data:AddItems`, `Data:AddNames`,
`RegisterModule`, `Query`) and has no SavedVariables. `ForeverLoot_Scraper` depends on it (it
tells new items from known ones by these rows). Rules for all addons are in the root
`CLAUDE.md`; the ownership contract is `docs/architecture.md`.

## Files (`ForeverLoot_Database.toc`, in load order)

- `db/generated/` — **generated by `npm run gen`, never hand-edited.** `generated.xml` loads
  `items/items_NNN.lua` (every scanned item, `itemsPerFile` rows each, `Data:AddItems`; the row
  layout is `Data.ITEM` in `ForeverLoot/src/data/data.lua` and must match `itemRow()` in
  `src/generate.ts`) and `locales/enUS/items.lua` (the English item names: the fallback name in
  every language and the second name search matches). The non-English item names stay in
  `ForeverLoot_Locale`. Excluded from LuaLS, StyLua and Prettier.
- `ForeverLoot_Database.lua` — registers the `items` module (`order = 1000`, `spacerBefore`,
  `query = true`, `columns = 2`, no children: the view runs `ForeverLoot.Query` over the whole
  DB and shows the search box and filter dropdown) and, at `PLAYER_LOGIN` (still behind the
  loading screen, after every addon's names have registered), runs one empty query so the sort
  order and search names are built before the first click on Items.
